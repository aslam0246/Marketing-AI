1. Project Overview

MarketingAI is a full-stack SaaS platform that enables businesses and content creators to automate their entire social media workflow using artificial intelligence. The platform removes the manual effort from content creation, scheduling, publishing, analytics, and strategy — replacing it with an AI-driven feedback loop.

Core Philosophy: Post → Publish → Collect Data → Analyze → Adapt → Post Better — every feature feeds into this closed-loop cycle.

✍️

AI Content Creation

Gemini-powered caption generation with tone, platform, and keyword customization.

📅

Smart Scheduling

Visual calendar and auto-publisher that posts at the exact scheduled time.

📊

Real-Time Analytics

Metrics synced live from Instagram and LinkedIn with per-post sentiment analysis.

🤖

Strategy Agent

3-module AI pipeline (Observe → Analyze → Plan) that generates data-driven weekly content strategies.

🔄

Adaptive Intelligence

Self-learning system that adjusts strategy weights based on actual vs predicted performance.

📡

Auto-Publisher

Background cron-based polling publishes scheduled posts without any manual action.

4. Frontend Code
4.1 Dashboard Layout — Auto-Publisher Polling

The dashboard layout is a client component that wraps all dashboard pages. It contains the sidebar navigation, notification bell, and critically — an auto-publisher that polls the backend cron endpoint every 60 seconds to trigger publishing of due scheduled posts.

app/dashboard/layout.tsx (key excerpt)
"use client";
import { useEffect, useRef, useState } from "react";
import { useAuth } from "@/context/AuthContext";

export default function DashboardLayout({ children }) {
  const { user } = useAuth();

  // ─── AUTO-PUBLISHER POLLING ──────────────────────────────────
  // Every 60 seconds, call the cron endpoint to publish due posts
  useEffect(() => {
    if (!user) return;

    // Trigger immediately on mount
    fetch("/api/cron/publish-scheduled")
      .catch(e => console.error("Cron trigger failed:", e));

    const interval = setInterval(() => {
      fetch("/api/cron/publish-scheduled")
        .catch(e => console.error("Cron trigger failed:", e));
    }, 60000); // 60 seconds

    return () => clearInterval(interval);
  }, [user]);
  // ─────────────────────────────────────────────────────────────

  return (
    <div className="flex min-h-screen bg-background">
      <Sidebar />
      <main className="flex-1 p-6">{children}</main>
    </div>
  );
}
4.2 My Posts Page — Delete Handler

The My Posts page shows three tabs: Drafts, Scheduled, and Posted. Each post card has a trash icon that calls the DELETE API with proper auth token and removes the post instantly from local state.

app/dashboard/posts/page.tsx (key excerpt)
const handleDelete = async (postId: string, status: string) => {
  if (!user) return;
  const label = status === "scheduled" ? "scheduled" : "draft";
  if (!confirm(`Delete this ${label} post? This cannot be undone.`)) return;

  setIsDeleting(postId);
  try {
    const token = await user.getIdToken();
    const res = await fetch(`/api/posts/${postId}`, {
      method: "DELETE",
      headers: { Authorization: `Bearer ${token}` }
    });
    if (!res.ok) {
      const err = await res.json().catch(() => ({}));
      throw new Error(err.error || "Failed to delete");
    }
    // Remove from local state instantly — no page reload needed
    setPosts(prev => prev.filter(p => p.id !== postId));
  } catch (error: any) {
    alert("Failed to delete: " + error.message);
  } finally {
    setIsDeleting(null);
  }
};

4.3 Authentication Context

A React context wraps the entire app and exposes the Firebase user object to all components via the useAuth() hook. The dashboard layout automatically redirects unauthenticated users to the login page.

context/AuthContext.tsx (key excerpt)
export function AuthProvider({ children }) {
  const [user, setUser] = useState<User | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const unsubscribe = onAuthStateChanged(auth, (firebaseUser) => {
      setUser(firebaseUser);
      setLoading(false);
    });
    return unsubscribe; // Cleanup on unmount
  }, []);

  return (
    <AuthContext.Provider value={{ user, loading }}>
      {!loading && children}
    </AuthContext.Provider>
  );
}

export const useAuth = () => useContext(AuthContext);
5. Backend Code
5.1 Auto-Publisher Cron Route

This Next.js API route acts as the scheduled publishing engine. It queries Firestore for all posts where status == "scheduled" and scheduledAt <= now, then calls the SocialMediaManager.publishPost() for each. It is triggered every 60 seconds by the dashboard polling.

app/api/cron/publish-scheduled/route.ts
import { NextResponse } from "next/server";
import { adminDb } from "@/lib/firebase-admin";
import { SocialMediaManager } from "@/lib/social-media-manager";

export async function GET() {
  console.log("[CRON] Checking for scheduled posts...");
  const now = new Date().toISOString();

  const snapshot = await adminDb.collection("posts")
    .where("status", "==", "scheduled")
    .where("scheduledAt", "<=", now)
    .get();

  if (snapshot.empty) {
    return NextResponse.json({ message: "No posts due", count: 0 });
  }

  let published = 0, failed = 0;
  for (const doc of snapshot.docs) {
    const post = doc.data();
    try {
      await SocialMediaManager.publishPost(doc.id, post.userId);
      published++;
    } catch (e) {
      console.error(`[CRON] Failed to publish ${doc.id}:`, e);
      failed++;
    }
  }

  return NextResponse.json({ published, failed });
}
5.2 Post DELETE API Route (with Ownership Check)
app/api/posts/[id]/route.ts — DELETE handler
export async function DELETE(req: Request, props) {
  const { id } = await props.params;

  // 1. Authenticate the request
  const authHeader = req.headers.get("Authorization");
  if (!authHeader?.startsWith("Bearer "))
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

  const token = authHeader.split("Bearer ")[1];
  const { uid } = await getAuth().verifyIdToken(token);

  // 2. Verify post exists and belongs to the user
  const docRef = adminDb.collection("posts").doc(id);
  const doc = await docRef.get();
  if (!doc.exists) return NextResponse.json({ error: "Not found" }, { status: 404 });
  if (doc.data()?.userId !== uid)
    return NextResponse.json({ error: "Forbidden" }, { status: 403 });

  // 3. Delete the document
  await docRef.delete();
  return NextResponse.json({ success: true });
}
5.3 Analytics Sync — Follower Snapshot Auto-Save

Every time the user clicks "Sync Fresh Data", the backend syncs post metrics AND automatically saves follower count snapshots from each connected platform to the follower_snapshots collection, with daily deduplication.

app/api/analytics/sync/route.ts (key excerpt)
// 3. Auto-save follower snapshots for each connected platform
const connectionsSnap = await adminDb
  .collection("users").doc(uid)
  .collection("connections").get();

for (const connDoc of connectionsSnap.docs) {
  const platform = connDoc.id;   // "instagram" | "linkedin"
  const connData = connDoc.data();
  let followerCount = 0;

  if (platform === "instagram") {
    const { InstagramConnector } = await import("@/lib/social/instagram");
    const connector = new InstagramConnector(connData.igAccountId, connData.accessToken);
    followerCount = await connector.getFollowerCount();
  } else if (platform === "linkedin") {
    const { LinkedInConnector } = await import("@/lib/social/linkedin");
    const connector = new LinkedInConnector(connData.linkedinId, connData.accessToken);
    followerCount = await connector.getFollowerCount();
  }

  if (followerCount > 0)
    await saveFollowerSnapshot(uid, followerCount, platform);
}
5.4 SocialMediaManager — Idempotent Publishing

The SocialMediaManager acts as an abstraction layer between the API routes and the platform-specific connectors (Instagram, LinkedIn, Mock). It includes idempotency guards to prevent double-publishing even if the cron runs multiple times for the same post.

lib/social-media-manager.ts (key excerpt)
static async publishPost(postId: string, userId: string) {
  const postRef = adminDb.collection("posts").doc(postId);
  const post = (await postRef.get()).data();

  // ── Idempotency: skip if already published or in-progress ──
  if (post?.status === "published" || post?.status === "publishing") {
    console.log(`[IDEMPOTENCY] Post ${postId} is already ${post.status}. Skipping.`);
    return { success: true, skipped: true };
  }

  // ── Mark as "publishing" to prevent race conditions ────────
  await postRef.update({ status: "publishing" });

  // ── Route to the correct platform connector ─────────────────
  const platform = post?.platform;
  let connector: SocialConnector;

  if (platform === "Instagram") {
    const conn = await getUserConnection(userId, "instagram");
    connector = new InstagramConnector(conn.igAccountId, conn.accessToken);
  } else if (platform === "LinkedIn") {
    const conn = await getUserConnection(userId, "linkedin");
    connector = new LinkedInConnector(conn.linkedinId, conn.accessToken);
  } else {
    connector = new MockConnector(platform);
  }

  const platformPostId = await connector.publish(post.content, post.imageUrl);
  await postRef.update({
    status: "published",
    platformPostId,
    publishedAt: new Date().toISOString()
  });
  return { success: true, platformPostId };
}

6.1 GeminiClient — Multi-Model Fallback Chain

All AI text generation is routed through a single GeminiClient class with a cascading fallback strategy. If the primary model is rate-limited or quota-exhausted, the system automatically tries the next available model.

lib/gemini-client.ts (key excerpt)
async generateText(prompt: string): Promise<string> {
  // Active models — updated March 2026 (deprecated models removed)
  const geminiModels = [
    "gemini-2.5-flash",      // Newest: 5 RPM free
    "gemini-2.0-flash",      // Stable: 15 RPM, daily quota
    "gemini-2.0-flash-lite", // Lightweight: separate quota
  ];

  for (const model of geminiModels) {
    try {
      return await this.callGeminiWithModel(model, prompt);
    } catch (e) {
      console.warn(`[Gemini] ${model} failed`);
    }
  }

  // Fallback: HuggingFace Zephyr-7B
  try { return await this.generateTextHF(prompt, hfKey); }
  catch (e) { console.warn("HuggingFace failed"); }

  // Final fallback: Pollinations.ai (no API key needed)
  return await this.generateTextFallback(prompt);
}
6.2 Strategy Agent — Observer Module

The Observer reads engagement metrics for each post and computes enrichment data including an engagement score, posting hour/day, hashtag extraction, and content category classification. This data powers the Analyzer.

lib/agent/observer.ts — Engagement Score Formula
// Weighted engagement score
// Likes(0.5) + Comments(0.3) + Shares(0.2)
// Comments weighted higher: require more intent than likes
const engagementScore =
  (0.5 * metrics.likes) +
  (0.3 * metrics.comments) +
  (0.2 * metrics.shares);

const engagementRate = (engagementScore / metrics.reach) * 100;

// Time enrichment
const publishedDate = new Date(post.publishedAt);
const postHour = publishedDate.getHours();       // 0–23
const postDayOfWeek = publishedDate.getDay();    // 0=Sun, 6=Sat

// Hashtag extraction
const hashtags = post.content.match(/#[\w]+/g) || [];

// Content category heuristic
const categorize = (text: string) => {
  if (/sale|discount|buy|launch|offer/i.test(text)) return "promotional";
  if (/tip|how to|guide|learn|fact/i.test(text)) return "educational";
  if (/you|comment|tag|what do you/i.test(text)) return "engagement";
  return "news";
};
